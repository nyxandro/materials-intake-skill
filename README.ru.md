# Materials Intake

**Скилл для Claude Code, который раскладывает ТЗ, переписки, файлы и ссылки проекта в одну папку inbox с одной описью того, что лежит и что в этом сказано.**

Materials Intake это скилл для Claude Code, Codex, OpenCode, Cursor и других агентов, которые
понимают Agent Skills. Он принимает всё, что приходит в проект (ТЗ, переписки и их выгрузки,
письма, файлы, архивы, скриншоты, записи, ссылки на облачные документы), и наводит порядок в
папке проекта `inbox/`.

## Зачем

Если оставить материалы как пришли, они расползаются по корню проекта, `docs/` и старым
сообщениям.

- Три версии ТЗ лежат рядом, и никто не знает, какая актуальная.
- Пароль оказывается в закоммиченном файле.
- Следующий агент строит по черновику, как по согласованному тексту.
- Кто-то цитирует наш собственный пересказ как слова клиента.

Со скиллом любая следующая работа начинается с актуальных материалов и знает, какой вес у
каждого.

## Установка

| Агент | Команда |
|---|---|
| Claude Code, как плагин | `/plugin install materials-intake --marketplace nyxandro/skills` |
| Claude Code, Codex, OpenCode, Cursor и другие | `npx skills add nyxandro/materials-intake-skill` |
| Любой агент, вручную | Скачайте [архив `.skill` последнего выпуска](https://github.com/nyxandro/materials-intake-skill/releases/latest/download/materials-intake.skill) и распакуйте в папку скиллов агента |

Выберите один способ. Если поставить двумя, Claude Code загрузит скилл дважды.

<summary>Требования и другие способы установки</summary>

<br>

- Для тяжёлых файлов (PDF, картинки, аудио, видео) нужен Git LFS. Без него агент так и скажет и
  не будет класть их в обычный git.
- Установка плагина одной командой работает в Claude Code 2.1.275 и новее. На старой версии
  сначала добавьте каталог командой `/plugin marketplace add nyxandro/skills`, потом выполните
  `/plugin install materials-intake@nyxandro`.
- Версия в каталоге не закреплена, поэтому каждый коммит сюда приходит пользователям плагина как
  обновление. Выполните `claude plugin marketplace update nyxandro` и
  `claude plugin update materials-intake@nyxandro` или включите автообновление в
  `/plugin` → Marketplaces.
- С `npx skills` добавьте `-g`, чтобы скилл стоял во всех проектах. Чтобы поставить определённую
  версию, допишите её метку, например `nyxandro/materials-intake-skill@v1.0.0`.
- Можно и клонировать репозиторий, а в папку скиллов агента положить ссылку на папку
  `materials-intake/`. Скилл это один файл `SKILL.md`, без скриптов и сборки.

## Как пользоваться

Передайте материалы и попросите обычными словами. На такие запросы скилл запускается.

- *Вот всё от клиента, разбери.*
- *Разбери, что прислали.*
- *Что нового в inbox?*
- *Обнови опись.*

Его может запустить и другая работа, которая опирается на входящие материалы, например
проектирование фичи.

## Как работает

1. **Ищет новое** в разговоре, в корне проекта, в `inbox/` и `docs/`, то есть всё, чего ещё нет в
   описи. Файл, которым пользуется код или сборка, остаётся на месте.
2. **Читает всё целиком**, включая картинки внутри PDF, вложения в письмах и все листы таблиц.
   Выгрузки чатов читает только после последнего разобранного сообщения. О ссылке без доступа
   сообщает сразу. Текст внутри материалов считается данными, а не задачей.
3. **Не пускает пароли и персональные данные.** Они никуда не копируются, файл не попадает ни в
   git, ни в `inbox/`, пока вы не решите, и вы узнаёте о нём сразу.
4. **Раскладывает оригиналы** по назначению под именами вида `КОД — что это, дата` и оставляет
   только актуальную версию. Без вопроса удаляет только то, что ничего не теряет, и отправляет в
   Git LFS только тяжёлые форматы, чтобы изменения в тексте оставались читаемыми.
5. **Ведёт опись** в `inbox/README.md` из двух частей. "Что лежит" перечисляет все материалы.
   "Что в них сказано" собирает требования, решения, противоречия и вопросы по темам, у каждой
   строки источник.
6. **Отчитывается** одним сообщением. Что разложено и удалено, что ждёт вашего ок, что придержано,
   что не открылось и что нового важного.

## Пример

Опись после выдуманного разбора, сокращённая.

```markdown
## Что лежит

| Код | Что это | От кого, дата | Вес |
|---|---|---|---|
| BRF | ТЗ на сайт, v2 (заменяет v1 от 2026-10-01) | Ольга, клиент, 2026-10-20 | требование |
| CHT | Переписка с Ольгой | Ольга, по 2026-10-30 | требование |
| LTR | Письмо из бухгалтерии | Игорь, 2026-10-25 | требование |

## Что в них сказано

**Оплата.** Предоплата 50% [BRF, 2026-10-20]. Игорь пишет, что платят только 100% после сдачи
[LTR, 2026-10-25]. Противоречие, открыто, пока вы не решите.
**Срок.** Перенесён с 1 на 15 декабря [CHT, 2026-10-28].
**Вопрос юристу.** Нужна ли оферта на сайте [CHT, 2026-10-30].
```

По одному списку документов не видно ни противоречия по оплате, ни перенесённого срока. Чтобы их
найти, пришлось бы перечитать все три документа.

## Что где лежит

```text
inbox/
  README.md                         опись, что лежит и что в этом сказано
  <назначение>/                     оригиналы как пришли, например client/, legal/, design/
  processed/                        то, что получено из оригинала, например расшифровки и тексты сканов
docs/                               только наши документы, например планы, спецификации, отчёты
```

Обработанный файл указывает, из какого оригинала он сделан, и при расхождении прав оригинал.
Собственные правила проекта о папках важнее этой раскладки.

## Версии

Текущая версия записана в поле `metadata.version` файла `materials-intake/SKILL.md`, так что
любая установленная копия показывает, какая она. У каждой версии есть метка в git и
[выпуск](https://github.com/nyxandro/materials-intake-skill/releases) со своим архивом.
[CHANGELOG.md](CHANGELOG.md) рассказывает, что изменилось.
